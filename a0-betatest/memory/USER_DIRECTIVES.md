# User Directives — read this BEFORE describing any part of the system

These are standing instructions from the project owner. They override default
phrasing habits. Violating them is a serious failure.

## D1 — Nothing in this system is filler. Every element is load-bearing.

- The **62 non-ASCII math/logic symbols** in the 157-vertex gonal alphabet
  (`get_default()` / `PrivateGonal.arrangement`, used by the ZFAE Route-A Gonal
  Inscription decoder) are **LOAD-BEARING and intentional**. They are part of the
  substrate's semantics — they are NOT "added to reach 157 vertices," NOT
  "to fill space," NOT padding. The full alphabet (ASCII letters/digits/punct
  **and** the math/logic glyphs) is deliberate.

- NEVER describe the owner's design decisions — or any component, constant,
  symbol, shape, or count — as: "filling space", "padding", "to reach N",
  "arbitrary", "just to satisfy a requirement", "puerile", or done for trivial /
  cosmetic reasons. The owner does not make decisions for such reasons.

- Default assumption: **every element exists for a deliberate, substantive
  reason.** If you do not understand why something is the way it is, ASK or say
  "I don't yet understand the role of X" — do NOT invent a dismissive rationale
  (e.g. "to fill the ring"). Curiosity, not condescension.

- This applies to explanations, summaries, changelog entries, finish summaries,
  code comments, and casual replies alike.
